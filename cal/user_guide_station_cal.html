📊 測站數量查詢網頁 - 使用手冊

本系統以「條件卡片」組合篩選全臺測站，即時統計數量、列出清單、匯出 CSV，並可繪製分布圖。本文件前半說明操作方式，後半的「篩選條件對照」與「附錄」詳細記錄每種條件如何從 stationData.json 取值與判斷，供日後維護參考。

🎯 1. 交互過濾池操作規則

將左側卡片加入過濾池，即可自由組合出複雜的篩選條件：

  • 加入條件：把卡片拖曳到「🟢 包含池」或「🔴 排除池」；也可以點一下卡片（或用 Tab 移到卡片後按 Enter），直接加入包含池。NEW
  • 同一張卡片內【勾選多個 = 或 (OR)】：在「縣市」同時勾選臺北市與新北市，會抓出屬於臺北市或新北市的測站。
  • 不同卡片之間【疊加 = 且 (AND)】：同時放入「縣市（臺北市）」與「傳輸方式（4G）」，只會留下兩者都符合的測站。
  • 包含與排除【扣除邏輯】：以包含池的結果為基準，再扣除符合排除池任一張卡片的測站。
  • 同一張卡片不能重複放進同一池：重複加入時，畫面會提示「已在包含池中」，並讓既有的卡片閃爍一下。同一張卡片可以同時出現在包含池與排除池。NEW
  • 調整空間：兩池中間的深色拉伸線可上下拖曳。
  • 一鍵清空：右上角「🗑️ 清空條件」會清除所有條件與手動剔除，並恢復預設（排除未上架）。

⭐ 2. 常用查詢與分享連結 NEW

🔗 分享查詢條件

每次調整條件，瀏覽器網址都會自動加上 ?q=…，記錄包含池、排除池與手動剔除的所有設定。點過濾池右上角「🔗 分享」可複製這個網址，同事開啟後會看到完全相同的條件與結果。重新整理頁面時條件也不會消失。

預設條件（只排除未上架）時網址不帶參數。若網址中的某個選項在新版資料中已不存在（例如中繼站改名），會略過該選項並提示。

⭐ 常用查詢

點「⭐ 常用查詢 ▾」：

  • 內建查詢：所有人都看得到，例如「署屬站（正式上架）」、「無線電傳輸測站」、「外單位雨量站」、「未上架測站」。
  • 我的常用查詢：點「＋ 將目前條件存為常用查詢…」並輸入名稱即可儲存，按 ✕ 刪除。只存在這台電腦的這個瀏覽器，換電腦或清除瀏覽器資料後就會消失；要長期保存或給同事使用，請用「🔗 分享」連結。

點任一查詢即套用，會取代目前所有條件。

🧭 3. 篩選運算流程（通用規則）

每次條件改變，程式（calculateStations()）會依下列順序計算：

  1. 起始清單：stationData.json 的 allStations 全部測站（目前 1,601 站）。
  2. 預設隱藏中繼站與區域中心：排除 is_hub === true（87 站）與 is_reg_center === true（12 站），因為它們是通訊節點而非一般觀測站。
    ⚠️ 例外：只要「測站類型」卡片出現在任一池，就不做這個預設隱藏，讓你能用測站類型挑出單／雙中繼站、區域站。
  3. 包含池：逐張卡片過濾，每張都必須符合（AND）。
  4. 排除池：符合任一張卡片的測站被扣除。
  5. 手動剔除：扣除在表格中「批量剔除」的測站。
  6. 排序：若使用者已點過表格標題排序，結果維持該排序。NEW
💡 預設條件：開啟網頁時，排除池已自動放入「上架狀態 = 未上架」，所以初始數量（目前 1,373 站）是「一般觀測站中已正式上架者」。
⚠️ 資料前處理：載入 JSON 後，initStationData() 會先替每一站算好衍生欄位（例如 _derivedUnit、_derivedTransport），篩選時直接比對這些欄位。另外，站碼 cwbid 為文字 "nan" 的測站（目前 16 站，都是未上架的備援站）會被視為沒有站碼。

📋 4. 14 種篩選條件對照

點擊各條件可展開「選項從哪裡來、比對哪個 JSON 欄位、怎麼判斷」。表中的 mappings.xxx 指 stationData.json 裡的代碼對照表。

1. 站碼規則篩選依站碼的開頭或特定位置字元篩選，可多條規則組合
比對對象cwbid（沒有時改用 sid），一律轉成大寫後比對
快速規則「46開頭（有人站）」：站碼以 46 開頭
「第2碼為2（農業站）」：站碼第 2 個字元為 2
自訂規則「開頭為」：站碼以輸入文字開頭（不分大小寫）
「特定位置」：第 N 碼等於輸入字元
多規則邏輯卡片上方選「符合任一（聯集）」或「符合全部（交集）」，套用於快速規則與自訂規則全部
注意事項卡片放進池中但尚未勾選或輸入任何規則時，這張卡片不影響結果（不會篩掉、也不會扣除任何站）。
程式位置matchStationCodeRule()、onCodeRuleInputChange()
2. 所屬單位中央署屬站、民航局、高公局、各外單位等管轄單位
JSON 欄位main_cat、sub_cat、vendor
衍生欄位_derivedUnit（getDerivedUnitString()）
判斷邏輯
  • main_cat ≠ 7：取 mappings.main[main_cat]，例如 署屬站、合作站、民航局、高公局、西濱、環境部
  • main_cat = 7（外單位雨量站）：改取 mappings.sub[sub_cat]，例如 農村水保署、翡翠水庫、石門水庫、第10河川局、水利署
  • 其中 sub_cat = 11（北市府）再依 vendor 細分：5 → 北市府大地工程處、6 → 北市府水利工程處、其他 → 北市府(其他)
選項來源全部測站 _derivedUnit 的不重複值，因此 JSON 新增單位時會自動出現
3. 測站類型氣象站、農業氣象站、空品站、區域站、雨量站、單／雙中繼站
JSON 欄位station_type
選項來源mappings.station_type 全部項目（目前 7 種）
判斷邏輯station_type 是否在勾選的代碼中
特殊行為只要這張卡片出現在任一池，就會取消「預設隱藏中繼站與區域中心」（見第 3 節）。要統計中繼站數量時，請用這張卡片。
4. 傳輸方式無線電、4G、實體網路、外單位雨量資料交換
JSON 欄位sub_cat
衍生欄位_derivedTransport（getTransportType()）
對照規則
sub_cat傳輸方式
8（區域站）無線電
3（農業站）、5（高公局）、6（西濱）、9（行動數據）4G
1（署屬有人站）、2（合作站）實體網路
10 ~ 15（外單位）外單位雨量資料交換
其他（4 民航局、7 環境部）未分類
選項來源程式內固定 4 個選項（不含「未分類」）
維護提醒⚠️ 民航局（17 站）與環境部（75 站）屬於「未分類」，不會被任何傳輸方式選項選到。目前這 92 站都是未上架，預設條件下不影響結果。若日後要納入，請修改 getTransportType() 並在 getOptionsByFilterId('transport') 加入選項。
5. 縣市選擇依測站所在縣市篩選，選項由北到南排列
JSON 欄位city（縣市代碼）
選項來源mappings.city 全部縣市，依程式內 NORTH_TO_SOUTH_CITIES 由北到南排序（不在清單中的排最後）
判斷邏輯city 是否在勾選的代碼中
連動同一池中若也有「鄉鎮選擇」，勾選縣市後鄉鎮清單只顯示該縣市的鄉鎮，已勾選但不屬於這些縣市的鄉鎮會自動取消。
6. 鄉鎮選擇依測站所在鄉鎮市區篩選；同名區會分開列出並標註縣市
JSON 欄位city + town
選項來源從全部測站整理出不重複的「縣市＋鄉鎮」組合（目前 361 組），依縣市由北到南、鄉鎮名稱排序。選項值為 縣市代碼-鄉鎮代碼，例如 22-71。
判斷邏輯測站的 city-town 組合是否在勾選值中
為何用組合⚠️ JSON 的 mappings.town 是依名稱編號，不同縣市的同名區共用同一代碼。目前有 6 個：東區（新竹市、嘉義市）、北區（新竹市、臺中市、臺南市）、中正區、中山區、信義區（基隆市、臺北市）、大安區（臺北市、臺中市）。若只比對 town，選「東區」會同時篩出兩個縣市的站。這些同名區在清單中會顯示成「東區（新竹市）」的格式。NEW
注意事項只會列出「有測站」的鄉鎮；沒有任何測站的鄉鎮不會出現在選項中。
7. 海拔高度輸入最低與最高公尺數，可新增多個區間
JSON 欄位alt（公尺）
判斷邏輯落在任一區間內即符合（多個區間之間為 OR），上下限都包含等於。最低留空視為不設下限，最高留空視為不設上限。
注意事項沒有 alt 的測站以 0 m 計算（目前資料中每站都有海拔，不受影響）。
8. 區域站歸屬12 個區域中心：宜蘭、花蓮、臺東、恆春、新竹、梧棲、臺北、臺中、日月潭、嘉義、臺南、高雄
JSON 欄位reg，以及 treeData["署屬站"]["區域站"] 的樹狀結構
選項來源程式內固定 reg 代碼 8 ~ 19，名稱取 mappings.reg
判斷邏輯符合以下任一即算：
  • 測站的 reg 等於勾選的代碼
  • 測站在 treeData["署屬站"]["區域站"][區域名稱] 底下（任意深度，依 sid 或 cwbid 對應）。這部分在載入時存成 _my_regional_boss。
連動同一池中若也有「中繼站選擇」，勾選區域後，中繼站清單只顯示 reg 屬於這些區域的中繼站。
維護提醒⚠️ 代碼 8 ~ 19 是寫死的。若 mappings.reg 的區域中心代碼有變動，請修改 getOptionsByFilterId('regional-center')。
9. 中繼站選擇選出經由指定中繼站傳輸的測站（含多層轉傳）
JSON 欄位is_hub、repid、n（站名）
選項來源所有 is_hub === true 的測站（目前 87 站），依 reg 再依站名排序；選項值為中繼站站名
衍生欄位_upstream_relay_names：從測站的 repid 開始，一層層往上找上層站，把沿途所有站名記下來（最多 20 層，防止資料循環）
判斷邏輯勾選的中繼站名稱出現在該站的 _upstream_relay_names 中，也就是該站直接或間接經由此中繼站傳輸
維護提醒以站名比對，若日後出現同名中繼站會被視為同一站。目前沒有同名中繼站。
10. 氣象資料頻率1 分鐘或 10 分鐘傳輸；純雨量站不參與
JSON 欄位sub_cat
衍生欄位_derivedWeatherFreq（getWeatherFreq()）
對照規則sub_cat 10 ~ 15 → 「不接受篩選(純雨量站)」；sub_cat = 8 → 10分鐘；其他 → 1分鐘
注意事項外單位雨量站（sub_cat 10 ~ 15）沒有氣象資料，不會被 1 分鐘或 10 分鐘選到。
11. 雨量資料頻率1 分鐘或 10 分鐘傳輸
JSON 欄位sub_cat
衍生欄位_derivedRainFreq（getRainFreq()）
對照規則sub_cat 10 ~ 15（外單位）→ 10分鐘；其他 → 1分鐘
12. 維護廠商負責維護的廠商或單位，十河分署再細分轄區
JSON 欄位vendor、reg
衍生欄位_derivedVendor（getDerivedVendorString()）
判斷邏輯
  • vendor ≠ 7：取 mappings.vendor[vendor]，例如 翰昇、勤睿、達元、北市府大地處
  • vendor = 7（十河分署）依 reg 細分：23 → 十河分署-翡翠水庫、24 → 十河分署-石門水庫、25 → 十河分署-第10河川局、其他 → 十河分署
選項來源全部測站 _derivedVendor 的不重複值，但不列出「未知」
13. 測站上架狀態正式上架或未上架（預設排除未上架）
JSON 欄位station_publish、publish_reason
衍生欄位_derivedStatus：station_publish == 0 → 未上架，其他 → 正式上架
預設開啟網頁與「清空條件」後，排除池會自動放入「未上架」（initDefaultFilters()）。要查未上架站，請把排除池的這張卡片移除，或在包含池勾選「未上架」。
顯示未上架站在表格中以灰色斜體顯示，滑鼠移上去可看到 publish_reason（暫不上架原因）。
14. 資料供應狀態官網、PDS、資料申購、Open Data 各資料集
JSON 欄位data_supply：物件格式，例如 {"1": 1, "2": 0, ...}，鍵為管道代碼，值為 1 代表有供應
衍生欄位supply_channels：值為 1 的管道，經 mappings.data_supply 轉成名稱的陣列，例如 ["官網", "O-A0002"]
選項來源程式內固定 8 個選項：官網、PDS、申購、O-A0001、O-A0002、O-A0003、O-A0005、O-A0091
判斷邏輯測站的 supply_channels 含有任一勾選項目
維護提醒⚠️ 選項的值必須與 mappings.data_supply 的名稱完全相同（目前一致）。若 JSON 改名或新增資料集，請同步修改 getOptionsByFilterId('public')，否則該選項會篩不到任何站，而且不會出現錯誤訊息。
🚧 「觀測項目」與「建站日期」兩張卡片為建置中，等後端資料準備好後開放。

🔍 5. 搜尋、資料表與匯出

✨ 多關鍵字模糊搜尋

在左側搜尋框輸入站名、站碼、縣市或鄉鎮。可用空白分隔多個關鍵字，例如 花蓮 國小，會找出同時符合的測站（「台」與「臺」視為相同）。最多列出 15 筆，按「定位」或 Enter 會選第一筆。搜尋範圍是全部測站，不受篩選條件影響。

✨ 勾選與批量剔除

勾選表格前方的核取方塊（支援全選），再按「🗑️ 批量剔除」，可把這些站從本次結果中隱藏，匯出 CSV 與分布圖也會同步排除。要恢復時，點上方條件摘要中「🗑️ 手動剔除」標籤的 ↩️ 復原，其他篩選條件不受影響。NEW

✨ 表格點擊排序

點表格標題（ID、站名、縣市、鄉鎮、高度）切換升冪 🔼／降冪 🔽。排序設定會保留：調整篩選條件後，結果仍依同一欄排序；已勾選的列也不會因為排序或調整條件而被清掉。NEW

📥 匯出 CSV NEW

匯出的檔案前 4 列記錄查詢條件、匯出時間、資料更新時間與測站數，空一列後才是表頭與資料，日後翻閱就知道這份清單是怎麼篩出來的。若要用程式讀取這個 CSV，請略過前 5 列。

欄位：原始站碼、正式代碼、站名、縣市、鄉鎮市區、緯度、經度、高度、傳輸方式、所屬單位、維護廠商，以及新增的測站類型、區域站歸屬、直屬中繼站、上架狀態、未上架原因、資料供應管道。

🕒 資料更新時間 NEW

「📊 統計結果區」標題右側顯示 stationData.json 的最後更新時間（取自伺服器回應的 Last-Modified），用來判斷數字是否為最新。若伺服器沒有提供，會顯示「無法取得」。

✨ 表格與地圖連動

點表格任一列，會開啟地圖並定位到該站，顯示詳細資訊卡。此時地圖只顯示這一站；按「🗺️ 分布圖」即可回到顯示全部篩選結果。

📊 6. 分組統計 NEW

點測站清單上方的「📊 分組統計」，依目前的篩選結果統計各類別站數，不必匯出到 Excel 再做樞紐分析。

  • 列（分組依據）：選一個維度，例如縣市，表格列出各縣市站數、占比與長條。
  • 欄（交叉比較）：再選一個維度，例如傳輸方式，就變成「縣市 × 傳輸方式」交叉表，格子顏色越深代表站數越多，最右欄與最下列為合計。
  • 按「📥 匯出統計 CSV」可下載目前的統計表，同樣附上查詢條件與資料日期。
可選的分組維度與取值方式程式位置：GROUP_DIMS
縣市mappings.city[city]，由北到南排序
鄉鎮市區縣市＋鄉鎮（例：新竹市東區）
所屬單位、傳輸方式、維護廠商與篩選條件相同的衍生欄位 _derivedUnit、_derivedTransport、_derivedVendor
測站類型mappings.station_type[station_type]
區域站歸屬reg 為 8～19 時取區域中心名稱；否則取 treeData 中的歸屬；都沒有則為「（非區域站）」
直屬中繼站沿 repid 往上的第一層上層站；沒有則為「（無，直接傳輸）」
氣象／雨量頻率、上架狀態與篩選條件相同的衍生欄位
海拔區間固定分為 0–500、500–1000、1000–2000、2000–3000、3000 m 以上（程式位置：ALT_BINS）
資料供應管道supply_channels，可複選：一站可能同時計入多個管道，各類別加總會大於合計；沒有任何管道的站計為「無對外供應」

「合計」一律是不重複站數。類別順序：縣市依由北到南、海拔依區間大小，其餘依站數由多到少。

等級意義檢查項目
⛔ 錯誤會讓篩選、地圖或統計出錯，應修正資料座標缺漏或明顯錯誤、repid 指向不存在的測站、代碼不在對照表中、資料供應選項與 JSON 不一致、區域中心代碼對照
